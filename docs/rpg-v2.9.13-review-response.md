## 塔40階の判定

Lv12・仲間未育成の32/36→2/36は再現した。39階・41階は未育成36/36で、40階の3体ボス戦に壁が集中する。未育成のままの攻略は保証しない。ただし、既得の少量育成で幅広い条件の勝利が回復するため、育成を使う任意コンテンツとして今回は現数値を維持する。

Lv12は各仲間が独立して11能力pt・11SPを持つ。初期解放の守護戦士・僧侶それぞれに防御2pt＋生命の根(2SP)→守りの枝(3SP)を使用すると28/36勝に回復する。能力は2/11pt、SPは5/11しか使わず、各仲間に9pt・6SPを残せる。未配分からの追加配分・パネル取得は無料で、追加学習・レベル上げ・ガチャ・新装備・100Gリセットを要求しない。2人分の独立予算を用いる条件であり、パーティー合計2ptという意味ではない。

根パネル2つだけは12/36、HP4pt＋根2つは26/36、防御2pt＋防御枝は28/36、既存バランス育成は36/36。全ポイント消費を強制せず、防御選択が有効に働く。主人公能力・パネルと装備は各対照内で固定。Lv12が全ユーザーの標準到達Lvという実測はなく、育成利用率・実操作時間・装備収集時間は未測定のため、負担がないとは断定しない。

## 生成データの軽量化・SHA256

元比較13,587,788 bytes＋集計2,316,270 bytes=15,904,058 bytesを、内容を1 byteも変えずgzipへ移した。比較1,078,568 bytes＋集計115,485 bytes=1,194,053 bytes、約92.5%削減。追加の塔調査は217,040 bytes。manifestはraw/gzip双方のサイズ・SHA256を保持する。

- 元比較SHA256: `20deffe0342ee5ddf8fad7c477a3e16f6b1e8885911098493034101035f99cd0`
- 元集計SHA256: `bc4403aa5862204e326e0190badd61cdade2ad7be091b55576625cacae1904df`

`scripts/checkBalanceData.js`は元commitの固定SHA256も別途照合する。31,536行・768集計群・候補名・実装確認フラグ、破損gzipの検出、変更データ書込拒否、拒否後のarchive不変を検証する。writeBalanceDataも再生成時にraw SHA256一致を必須とする。

```sh
node scripts/checkBalanceData.js
node scripts/measureEnemyBalance.js --verify-after
node scripts/summarizeEnemyBalance.js
node scripts/investigateTower40.js
node scripts/checkBalanceData.js
```

raw JSONは標準gzipツールで.json.gzを展開できる。NodeからはreadBalanceData(pathWithoutGz)で読む。再生成は直接gzipへ書き出し、元の測定条件・全比較結果を維持する。初回--packはrawからの梱包用で通常再生成には不要。履歴は書き換えないため、e14d6d8の過去rawはGit履歴に残る。最新checkoutを軽量化する対応であり、過去履歴の削減は行わない。
